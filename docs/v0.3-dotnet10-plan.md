# v0.3 .NET 10 migration

User selected .NET 10 LTS modernization (2026-10-10). Existing authorization includes fork/push, Release, backup/uninstall/replace/install and Explorer restart.

## Design

Target net10.0-windows with Windows Forms and WPF enabled for the existing preferences/drawing paths. Use SDK-style project and explicit source/resource includes initially, preserving parser/rendering behavior. Expose only the four shell-handler classes through native .comhost.dll with their existing CLSIDs; assembly-wide COM visibility becomes false. Registration uses regsvr32 for the modern host plus bounded file-association management, and supports uninstalling the old Framework assembly during upgrade. Modern COM hosts are framework-dependent, so require the matching .NET10 Desktop Runtime (present locally) and validate it before changing registration. Keep x64 Windows Explorer as primary delivered architecture; test x86 decoder compatibility separately where runtime is available.

1. Inventory .NET10 incompatible APIs/dependencies; create failing migration/build contract tests and baseline regression inventory.
2. Convert production project/build to SDK style, port obsolete runtime APIs and eliminate Framework-only registration dependencies. Keep maintained interop fixes and modern resource support.
3. Migrate regression runners to .NET10; prove parser/streams/thumbnail/overlay/native decoder and actual COM activation. Validate preferences/resources separately from compiler success.
4. Modernize registration/packaging: explicit .comhost, deps/runtimeconfig, managed dependencies, translations and native libs; no use of RegAsm for new assembly. Retain old uninstall migration path and rollback.
5. Independently review, build/publish/run regressions and real APKs, then commit/push/tag/releasev0.3.0. Back up0.2.0.8 and deploy exact release files; test registered icon, thumbnail and info-tip callbacks, shared download writes and cache refresh.

Acceptance: target framework metadata and runtime evidence show.NET10; every existing behavior regression passes under.NET10; installed callbacks load modern COM host and match release hashes; original package bytes preserved. No promise of arbitrary modern drawable/split-container support beyond v0.2.
